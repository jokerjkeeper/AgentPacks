# /stopic — 關鍵詞按需載入主題頁

依使用者輸入（口語關鍵詞或一句需求）從 `wiki/` 找出相關主題頁並載入，供需求分析使用。

> 用途：企劃提需求時，用其口語（如 `技能冷卻`、`掉寶太少`、「想做排行榜」）對到對應模組頁（如 `主題-戰鬥`、`主題-背包`），
> 載入後即可分析「會動到哪些程式檔 / 可行性 / 拆解 / 開工單」。

## 0. 讀路徑

先讀 `.agent/config.json` 取 `paths.wiki`。

## 執行步驟

1. **讀路由表**：`<WIKI>/INDEX.md`（每列含 `模組｜摘要｜features｜別名｜頁面｜權威`，是 LLM 判讀素材）。
2. **語意判讀（為主）+ 關鍵詞（輔助）**：把輸入需求對照每列的 **摘要 / features / 別名 / 模組名**，由 LLM 判斷相關性——**不限字面子字串命中**，口語/同義/概念相近即算相關。
3. **多頁召回，依相關性處理**：
   - 一個需求常橫跨數模組（如「掉寶太少」→ 戰鬥＋掉落＋關卡資料）；把**所有相關頁**都 `Read` 載入，不要命中 1 筆就停。
   - 相關頁明確 → 全載並逐頁簡述涵蓋哪些 `## 功能` 與對應 `檔案:行號`（取 footnote）。
   - 相關但分散/不確定要全載 → 列出候選（模組 + 一句涵蓋範圍 + 相關理由），問使用者載哪些。
   - 確實無相關頁 → 回報知識空白：說明 INDEX 現有哪些模組、建議換說法或該主題尚未策展（需補 raw / 跑 `/curate`）。
4. **不臆測**：只呈現頁面已有內容（含 `authority`，區分 confirmed / 未確認）；INDEX 未涵蓋的不要編造。

## 規則

- 純讀取與載入，不改 wiki / 不碰 `.state`。
- aliases / INDEX 命中邏輯見 `.agent/spec/wiki.md` §5。

範例：`/stopic 技能冷卻`、`/stopic 掉寶太少`、`/stopic 排行榜 獎勵`。
