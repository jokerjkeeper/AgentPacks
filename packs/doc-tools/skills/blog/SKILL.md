# Blog 文章撰寫

根據 `.agent/blog/` 目錄下的素材文件，撰寫 Blog 文章。

## 核心原則

**本指令與其他指令不同：撰寫前必須先向用戶提問，確認條件後才開始撰寫。**

## 執行步驟

1. **讀取素材**
   - 掃描 `.agent/blog/` 目錄下的所有 `.md` 文件
   - 若指定了 `$ARGUMENTS`（如 `blog_1`），僅讀取對應文件
   - 若目錄不存在或無文件，提示用戶先建立素材文件
   - 素材文件格式參考下方「素材文件格式」

2. **向用戶提問（必須）**
   - 在撰寫前，必須向用戶確認以下條件，不可跳過：

   | 條件 | 說明 | 預設值 |
   |------|------|--------|
   | 字數 | 目標字數範圍 | 800 字 |
   | 風格 | 自然敘述、條列式、教學步驟、故事型、技術深度分析 | 自然敘述 |
   | 目標對象 | 一般讀者、技術人員、初學者、決策者 | 一般讀者 |
   | 語氣 | 輕鬆口語、專業正式、幽默風趣、簡潔直白 | 輕鬆口語 |
   | 語言 | 繁體中文、簡體中文、英文、日文 | 繁體中文 |
   | SEO 關鍵字 | 希望文章涵蓋的關鍵字（可選） | 無 |

   - 若素材文件中已指定部分條件，列出並請用戶確認或覆蓋
   - 等待用戶回覆後才進入下一步

3. **規劃文章大綱**
   - 根據素材與確認的條件，列出文章大綱：
     - 標題（含備選標題）
     - 各段落標題與要點摘要
     - 預估字數分配
   - 以清單形式呈現給用戶確認

4. **等待用戶確認大綱**
   - 確認無誤後才進入撰寫階段
   - 用戶修改後需重新呈現修改後的大綱

5. **撰寫文章**
   - 依據確認的大綱與條件撰寫完整 Markdown 文章
   - 文章結構：
     ```markdown
     # 標題

     > 一句話摘要（可作為 meta description）

     ## 前言
     ...

     ## 正文段落
     ...

     ## 結語
     ...

     ---
     <!-- metadata -->
     <!-- keywords: keyword1, keyword2 -->
     <!-- word_count: xxx -->
     <!-- date: YYYY-MM-DD -->
     ```

6. **輸出文件**
   - 輸出路徑：`./blog/` 目錄（專案根目錄下）
   - 檔名格式：`YYYY-MM-DD-<slug>.md`（如 `2026-03-23-my-first-blog.md`）
   - 若 `./blog/` 目錄不存在，自動建立
   - 告知用戶輸出路徑與實際字數

7. **後續調整**
   - 詢問用戶是否需要修改特定段落
   - 支持局部修改後重新輸出

## 素材文件格式

素材文件放置於 `.agent/blog/`，建議格式：

```markdown
# 文章標題

## 參考內容
- 要點一
- 要點二
- ...

## 條件（可選）
- 字數: 500
- 風格: 條列式
- 目標對象: 技術人員
- 語氣: 專業正式
- 語言: 繁體中文
- 關鍵字: Claude Code, AI 工具

## 參考連結（可選）
- https://example.com/reference
```

## 撰寫規範

- 標題簡潔有力，避免過長
- 開頭第一段須能吸引讀者繼續閱讀
- 適當使用小標題分段，提升可讀性
- 避免空泛的填充文字，每句話都要有資訊量
- 若為技術文章，程式碼範例須可執行且有註釋
- 結語提供行動呼籲或總結觀點，不要虎頭蛇尾

## 參數

- `$ARGUMENTS`：指定素材文件名（不含副檔名）或簡要主題描述（可選）
